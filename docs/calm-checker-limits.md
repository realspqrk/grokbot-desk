# Calm checker limits and provisional amendments

Known limit K visibility: a descendant that restores `visibility: visible` inside a `visibility: hidden` subtree is not measured.
Known limit K4/K6/K11: generated pseudo-element text uses incomplete font, colour, and meta-noise evidence.
Known limit K8: unlabelled secondary sections cannot be recognized semantically without author markup.
Known limit K10: the checker verifies reachable platform states but cannot prove semantic equivalence between previews or approval states.

Provisional K1 amendment: a disabled primary may use a neutral opaque fill when its label has AA contrast and no element is accent-filled.
Provisional K2/K9 amendment: an attached, accessibly named copy control no larger than 32 px is exempt, and a roving radiogroup, toolbar, or tablist counts as one control.
K5 treats an element marked `data-rs-avatar` that is at most 32x32 px and holds nothing but an optional `<img>` as media (like an image), not a container box; larger or content-holding avatars count as boxes again (`tests_js/calm.test.mjs`).
Identity calibration adds scenes per template golden (custom accent `#0891b2`, whose derived hover fill requires the light-theme fallback; low-contrast accent `#f6c945` with the light-theme fallback; 3 open runs whose other bots carry other accents) and checks the active accent and that no accent is painted in the strip.
Provisional K10 amendment: a tab's `aria-controls` may reference either its mockup or a tabpanel containing the mockup.
K10's social-preview audit (one wide mockup, stateful platform tabs, platform switching) runs for the built-in `preview-post` and any user template that `extends` `preview-post` (`isSocialPreview` in `tools/calm.mjs`).
K3 now judges the avatar strip (`.rs-strip` / `[data-rs-strip]`; legacy `.rs-rail` / `nav[aria-label*="run"]` pages are still read). With exactly 1 open run the strip must not render (0 px, nothing focusable); with 2+ open runs it must render. Facts renamed `strip_rendered` / `strip_width` (and the identity scenes' `strip_accents`). The strip is one Tab stop (roving tabindex in a `role=toolbar`), so K2/K9 count it as one control. Only the shell's own strip counts as the report switcher: `#rs-strip` inside `#rs-strip-nav`, outside the template mount `#rs-mount`, every entry a report (`data-run-id`); templates may not use `data-rs-strip`/`data-rs-rail` or the strip ids (template lint), and a marker inside template content is ignored, so a template toolbar keeps the normal arrow audit and its K2/K9 count. The Tab audit (`tools/e2e.mjs` `auditStripArrows`) arrows through the switcher once around: each ArrowRight must move the focus to the next entry with a visible ring, make that report the shown one (`aria-current`, one Tab stop, ready again) and wrap back to the report it started from; only then is the strip a verified roving group for K2/K9. It is audited last because each step re-mounts the template. The copy-focus audit (`tools/calm.mjs`) does not arrow through the switcher (it holds no copies). Not checked by K3: the "n of m open" count text, the underline of the active entry and auto-advance after a decision (covered by `tests_js/popup.e2e.test.mjs`). The done state after the last decision has no primary action and is not a calm scene.
